# 多账号登录与数据迁移（0.4.0）

## 使用方式

- 访问原站点，使用用户名和密码登录；登录页可切换到“注册”。无需admin审批，无邮箱验证或邮件找回流程。
- 用户名3–32位字母、数字或下划线，以字母开头；统一转为小写，唯一。密码12–128字符，数据库只保存加盐scrypt摘要。
- 新用户得到空白工作台。原有客户、订单、菜品、餐盒、店铺设置、旧九表、幂等记录和薄荷连接全部归属于test，内容不复制给新用户。test为普通数据所有者，无查看其他账号的权限。
- 账号菜单 → 账号设置，提供“密码”和“API / MCP 接入”Tab。密码更新后撤销全部登录会话，重新登录；已有机器凭据可在接入页逐个撤销。
- 登录会话7天，数据库保存随机会话的摘要；退出立即删除会话。HTTPS入口会启用Secure Cookie。支持显式配置的 HTTP 与 HTTPS 双入口，两端独立登录；HTTPS 在外部代理终止。
- 每账号可创建最多20个只读或可读写接入凭据，仅创建时显示明文；数据库只存摘要。MCP地址仍为 /mcp，13个工具复用当前调用者身份，不能指定别人的owner_id。

## API

| 路径 | 方法 | 作用/身份 |
|---|---|---|
| /auth/register | POST | username/password/displayName；自行注册并登录；要求正确Origin |
| /auth/login | POST | username/password；正确Origin；返回用户和Cookie |
| /auth/logout | POST | 撤销当前Cookie会话；正确Origin |
| /auth/me | GET | 当前用户id/username/displayName |
| /auth/password | POST | 当前浏览器登录；currentPassword/password；撤销所有会话 |
| /auth/tokens | GET/POST | 当前浏览器登录；仅列出自己的凭据元信息或创建新凭据，name/scope(read/write) |
| /auth/tokens/:id | DELETE | 当前浏览器登录；撤销自己的凭据，其他账号id返回404 |

所有业务接口和MCP必须认证。请求体、查询参数或Headers中的用户ID不能改变归属；owner_id只由数据库验证过的登录态或凭据确定。只读凭据不能执行写操作，也不能创建更高权限凭据。修改操作有同源检查；登录与注册有限频。单实例内存限频在容器重建后重置，不宣称分布式防护。

## 部署与原数据迁移

1. 保留当前镜像和配置；停止当前app写入，执行原库一致性备份。保留原业务库连接，不用新建空库代替。
2. 在私有环境配置 INITIAL_PASSWORD，作为test账号首次迁移密码；不写入公开包。兼容迁移可回退使用原APP_ACCESS_TOKEN，完成后不靠环境密码重新认证。
3. 使用目标镜像独立运行 node scripts/migrate.js，再启动应用（AUTO_MIGRATE=false）。可重复执行，不覆盖用户密码或已有数据。迁移将旧12表增加owner_id=1并建立复合主键、账号外键；旧唯一约束改为账号内唯一。最终共15张表，14个账号归属外键。
4. 原APP_ACCESS_TOKEN/APP_READ_TOKEN仅首次导入为test的机器凭据摘要。原网页口令登录被账号密码登录替代。凭据撤销后重新迁移不会复活。
5. 验证test旧数据内容摘要、原12表投影摘要、账号归属、API/MCP和公网登录页。生产验收不新增测试业务账号。

## 恢复边界

0.4.0的表结构和身份边界与旧版不兼容。禁止只切回0.3.0镜像接着使用多账号库，这可能读取多个账号的数据。回退演练仅使用升级前备份恢复出的独立数据库。生产如需恢复，应先停写并保留升级后完整备份，评估新增账号和数据后选择前向修复或隔离恢复，不能覆盖新用户数据。

## 交互与验收要求

登录/注册使用Tab；账号入口为下拉菜单；设置弹窗保留原业务上下文；关闭返回焦点，未保存输入需确认放弃。覆盖360/390/430px与桌面宽度。实际注册、隔离写入、权限、改密/退出、凭据撤销在隔离Docker/MySQL内测试；浏览器检查表单、切换、错误提示、账号菜单、弹窗、数据回读和布局。薄荷真实在线服务仍需用户有效密钥，不把模拟provider验证冒充真实薄荷调用。
